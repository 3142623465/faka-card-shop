发卡网系统「分站」模块审查报告

围绕分站（代理商）体系的上下级关系、资金流、商品分销与前后端实现，逐文件核对后给出问题定位、影响评估与改造建议。审查范围覆盖后端 server/routes/branch.js、admin.js、user.js、shop.js、settle.js、auth.js 与前端 public/js/branch.js、app.js、admin.js。

项目目录：D:\faka 数据库：JSON 文件 / MongoDB 双模式 审查方式：静态代码走查 共发现 17 项问题

结论摘要

分站模块的「招募-开通-升级」主链路（上下级关系、邀请链接、余额扣款）基本可用，测试脚本 scripts/test-branch-products.js 覆盖了主要正向流程。但存在 3 项 P0 级结构性缺陷，会导致整个分站模式无法闭环：

  • 卖货不赚钱：分站店铺的商品售卖与分站收益完全脱钩——订单不记录归属、分站没有任何订单/发货/卡密接口，分站上架商品卖出去后收不到一分钱，也管不了自己的单。
  • 赚了提不出：分站余额只有进账没有出口——无提现、无转出、无消费场景，管理端也无法调整分站余额，且所有资金变动都没有流水记录。
  • 管理员建的分站是"半残"体系：管理员开通的分站 ownerId=0，其下普通分站永远无法升级为专业分站；两条创建下级路径（邀请链接 vs 后台直开）的价格继承规则还不一致。

管理员创建的分站体系断裂：无法升级、无法绑定用户
管理员开通分站固定 ownerId=0；专业分站后台直开的普通分站（POST /branches）不写 ownerId。而 upgrade 路由要求 owner 必须存在，否则报"分站关联用户不存在"——管理员体系下的普通分站永远无法升级为专业分站。管理员也无法将分站绑定到用户账号（无此功能）。
影响：最常见的"管理员建站"场景下升级功能不可用；用户端/独立后台双轨数据不统一。		 ① 管理员开通分站时可选关联用户（手机/邮箱）或提供事后绑定接口；② upgrade 对无 owner 分站改为从 branch.balance 扣款或先要求绑定；③ 统一两条创建路径的数据结构（ownerId、价格字段）。

两条创建下级路径的价格继承不一致
邀请链接 join-branch 创建的子站继承上级 pricePro/priceNormal；专业分站后台直开的普通分站（POST /branches）不设置价格字段 → 展示与后续定价全部回退到全局设置值。
影响：同级分站看到的价格体系不一致，子站升级后的定价与上级设定脱节。		 统一两条路径：都继承上级价格并落库；或都不继承、统一从全局读取，并在 UI 明示"价格来源"。
同时 /branch/me 对无价格字段的子站应显示父级价格而非全局价。

分站密码与用户密码单向同步，双入口语义混乱
用户改/重置密码 → syncBranchPassword 强制覆盖名下分站密码（即使分站单独改过）；分站后台改密码（PUT /branch/password）不回写用户密码。两个入口互相覆盖，用户会突然登不上其中一个。
影响：密码体系混乱，账密冲突投诉多。		 明确单一来源：方案A 用户密码为唯一来源（分站后台不允许改密）；方案B 分站独立密码（用户改密不再同步）。建议方案B + 首次登录强制设置分站密码，并在两个入口文案说明。

商品价格下限链存在断裂场景
① 总站删除源商品后，分站副本 sourceId 悬空，改价时 floor 回退为自身价格，下限约束消失；② 上级下架同款后，子站可改到低于上级原价（findParentPrice 只找 status===1）；③ 接口返回 floor: p.floor（字段不存在，应为局部变量）。
影响："价格不能低于上级同款、层层生效"的承诺在边界场景失效。		 ① 分站商品保存"当前下限价"快照（创建/上级改价时刷新）；② 上级下架时仍以上架前价格作为下限；③ 修正响应字段 floor 为实际计算值。
12P2后端 routes/branch.js:261-284
分站商品为一次性快照，与总站数据不同步
上架时复制名称/详情/图片/库存；总站改价、改名、改详情、补充卡密后分站副本不联动；分站商品强制 manual 类型，库存是上架瞬间快照，卖完即"0"。
影响：分站店铺信息陈旧、库存失真，顾客体验差。		 ① 提供"一键同步"（按 sourceId 刷新名称/详情/图片/价格基线）；② 或前台展示时按 sourceId 实时回源总站价格与库存（价格仍需受下限约束）。
